# Вимоги до Agent Harness (Harness Requirements)

## 1. Джерела даних агента
- Документація проєкту (`docs/`) та база знань (Obsidian vault у сусідньому репозиторії через MCP-конектор).
- Вихідний код застосунку (`src/`).
- Історія комітів Git та конвенції повідомлень.
- Результати виконання тестів та логи CI/CD.

## 2. Цільові задачі агента
- Генерація boilerplate-коду для нових модулів та моделей.
- Написання unit-тестів (Pytest) із покриттям від 80%.
- Автоматичне форматування та рев'ю коду.

## 3. Рівні Guardrails (Обмеження дій агента)
- **Allow (Дозволено без обмежень):** Читання файлів, аналіз коду, запуск локальних тестів, пошук по базі знань.
- **Warn / Require Approval (Потребує підтвердження людиною):** Модифікація існуючих бізнес-модулів, створення комітів, зміна конфігурацій середовища.
- **Block (Безумовно заборонено):** Видалення файлів проєкту, прямий пуш у захищені гілки, зміна системних конфігурацій поза межами проєкту.
