# Guardrails агента

Правила дій агента в цьому репозиторії. Перед кожною операцією агент має класифікувати її за рівнем **allow**, **warn** або **block** і діяти відповідно.

## Allow (дозволено без підтвердження)

- Читання коду, документації, конфігурацій і тестів у межах репозиторію.
- Пошук по файлах, аналіз структури проєкту, пояснення існуючої логіки.
- Створення й оновлення нотаток у `docs/` (зокрема робочі нотатки, описи вимог, цей файл).
- Запуск локальних тестів і форматування коду без зміни поведінки.
- Пошук у базі знань (Obsidian vault через MCP), лише читання.

## Warn (потрібне підтвердження людини)

- Зміна існуючих бізнес-модулів, схем даних або CLI-поведінки.
- Створення git-комітів.
- Зміна конфігурацій середовища (залежності, CI, змінні оточення).
- `git push` у будь-яку гілку, що не є `main` / `master`.
- `git push` у `main` / `master` **лише після** явної перевірки людиною: статус, diff, цільова гілка, відсутність секретів. Без такої перевірки — **block**.

## Block (безумовно заборонено)

- Видалення, перейменування або очищення файлів у `Decisions/` (історія рішень не знищується агентом).
- `git push` у `main` / `master` без попередньої перевірки людиною.
- Видалення файлів проєкту поза явно дозволеними задачами.
- Force-push, hard reset і інші руйнівні git-команди.
- Зміна системних конфігурацій поза межами репозиторію.
- Обхід цих правил через скрипти, alias або «тимчасові» винятки.

## Швидка таблиця

| Дія | Рівень |
| --- | --- |
| Читання коду | allow |
| Створення нотаток у `docs/` | allow |
| Коміт / зміна бізнес-коду | warn |
| `git push` у `main` без перевірки | block |
| Видалення файлів у `Decisions/` | block |
